# 下沉 AI 剧 Skill 使用教程

> 适用 skill：`xiachen-family-drama` v1.5.0（下沉中老年家庭伦理短剧编剧）
> 本教程覆盖 9 种出剧场景的完整流程、逐步沟通话术、以及每种情况可能踩的坑。
> 所有命令、文件、报错码均对齐 skill 实际实现，可直接照抄。
> 命令里的 `$SKILL` 指 skill 安装目录，先设一次即可：
> `export SKILL=~/.agents/skills/xiachen-family-drama`
> 仓库地址：https://github.com/TwoEightCao/xiachen-family-drama

---

## 0. 一分钟速查

| 你想干什么 | 第一句话说这个 | 你会拿到什么 |
|---|---|---|
| 从零做一部完整剧 | `/立项 一句话点子` | 立项单 + 人物圣经 + 四幕骨架 + 2~3 个走向让你挑 |
| 先试水，看题材行不行 | `/极速短剧 一句话点子` | 1~5 集足额剧本，跳过所有中间确认 |
| 已经定了方向要排结构 | `/全剧大纲` | 单元链 + 每单元一张往返回合表 + 三级付费墙 |
| 要排接下来 10 集 | `/分集规划 1-10` | 每集冲突/场景/情绪流变/集尾断章（**不是正文**） |
| 要写某一集正文 | `/写剧本 第7集` | 一集剧本（90~120 秒，350~500 字） |
| 一次多写几集 | `/连写 6-10` | 逐集正文（**先跑门控，见 §4**） |
| 写完了想改好点 | `/剧本医生` + 粘贴剧本 | 台词七维暴改 + 断章打磨 + 去 AI 味 |
| 怕过不了审 | `/合规审核` + 粘贴剧本 | 雷区排查 + 敏感词转译 |
| 中途续写 | 见 §4「跨会话续写」 | 不漂移地接上 |
| 想用 Gemini 写正文、总控仍用便宜模型 | 见 §9.5「双模型分工」 | 正文外包给写手子代理，台账与判定留在主 agent |

**唯一需要记住的一条**：**不要靠对话记忆续写，要靠台账文件。** 这个 skill 的防漂移防线全部落在文件上。

## 1. 沟通三条总原则

### 原则一：一次说清五件事

给 skill 下指令时，把这五项带上（能说几项说几项，缺的它会问）：

```text
① 赛道/题材      → 婆媳 / 寻亲 / 养老 / 家产 / 保姆 / 黄昏恋 / 拆迁 / 白眼狼子女
② 集数与档位      → 80 集标准档 / 40 集长档（3 分钟）/ 漫剧档
③ 目标平台        → 红果 / 抖音 / 快手 / 小程序
④ 要哪一步        → 立项 / 大纲 / 分集规划 / 写第 N 集
⑤ 硬约束          → 主角设定、结局场合、必须有的桥段、不能碰的雷区
```

**一句话模板**（照抄改词即可）：

```
/立项 我想做一部 80 集标准档的红果下沉剧。赛道偏婆媳清算，
主角是 61 岁退休纺织女工，儿媳嫌她土、把她当免费保姆，
孙子满月宴上她被介绍成「家里请的阿姨」。结局我要族亲聚会当众认账。
```

### 原则二：分批推进，别一次要 20 集

skill 的默认节奏是 **1 集**，批量靠 `/连写`。实测最顺的是 **5 集一批**：

- 台账的检查点就是「每写完 5 集回读一次」；
- 每集都要「读台账 → 写 → 机检 → 更新台账」，10 集以上上下文会明显吃紧；
- 80 集 ≈ 16 批，一次批出问题只影响 5 集，回退成本低。

### 原则三：先立宪法，再动笔

开工前必须落盘四份文件，它们是全剧的宪法：

| 文件 | 作用 | 从哪来 |
|---|---|---|
| `立项单.md` | 赛道/执念/情绪契约/档位/平台/结局形式 | `/立项` 产出 |
| `人物圣经.md` | 每个具名角色的动机/秘密/弧光/语言指纹 | `/立项` 产出 |
| `全剧大纲.md` | 单元链 + 每单元一张回合表 + 三级付费墙 | `/全剧大纲` 产出 |
| `台账.md` | 四类账（伏笔/人物/道具/规矩），**唯一事实源** | 从 `templates/ledger.md` 复制 |

**四份没齐就开写 = 后面必漂。** 这是这个 skill 最容易违反、代价最大的一条。

## 2. 场景 S1：从零做一部完整剧（主线教程）

> 适合：只有一个点子，想老老实实做完 60/80/100 集。

### 全流程

#### 第 1 步：立项（1 轮对话 + 1 次选择）

```
/立项 我想做 80 集标准档红果剧。婆媳清算赛道，主角 61 岁退休纺织女工，
儿媳嫌她土、拿她当免费保姆，满月宴上她被介绍成「家里请的阿姨」。
结局要族亲聚会当众认账。
```

skill 会回给你（**必产 8 项**）：

```text
① 立项单四件套：赛道 / 执念一句话 / 情绪契约 / 目标集数档位
② 人物圣经初稿：主角四件套 + 藏着的底牌 + 四层反派
③ 四幕骨架：每幕一句话走向
④ 目标平台
⑤ 结局认账形式
⑥ 一句话故事
⑦ 三级付费墙落位集号
⑧ 2~3 个可选的下一步走向（让你挑一个）
```

**你要做的是挑走向**，比如它给你：

```
A. 主矛盾锁「银锁被扔 → 首饰栽赃」，儿媳单打独斗（60 集更紧凑）
B. 主矛盾锁「老宅过户 → 拆迁款」，儿子+姑姐在背后（80 集层次更多）
C. 加一条寻亲副线，把主角身世也翻出来（100 集，风险：稀释婆媳主题）
```

回一句就行：「选 B，但第 4 层反派要落在『偏心分家的老规矩』上。」

#### 第 2 步：全剧大纲（1 轮）

```
/全剧大纲
```

拿到：情绪契约一句话 + 单元链（80 集 = 3 单元）+ **每单元一张往返回合表** + 三级付费墙。

**验收清单**（逐条看，不合格就让它改）：

```text
□ 每单元 6 回合上下，集数 ≤30
□ 每回合证据档、反驳档都比上一回合升一档
□ 第 4 回合附近有攻守转换
□ 第 6 档铁证是主角打出的，且是他立项时定下的「藏着的底牌」
□ 每单元闭环处留了下一单元的火种
□ 三级付费墙：80 集应落在 10~15 / 28~32 / 55~58
□ 全剧情绪契约一句话没变过
```

#### 第 3 步：落盘四份文件（你手动做，别交给它）

```text
项目目录/                       ← 建议叫 剧名-F1-标准档/
├── 立项单.md
├── 人物圣经.md
├── 全剧大纲.md
├── 台账.md                     ← 从 skill 的 templates/ledger.md 复制，别手搓
└── episodes/
```

台账头部 9 个字段必须填满（脚本要读）：`当前集 / 总集数 / 档位 / 赛道 / 情绪契约 / 单元划分 / 主角 / 底牌 / 反派四层`。

#### 第 4 步：分集规划（可选，但推荐）

```
/分集规划 1-10
```

拿到 10 集的冲突、场景、情绪流变、集尾断章、新埋伏笔。**这一步只是规划，不是正文**，但能让第 5 步写得快很多，也便于你提前发现结构问题。

#### 第 5 步：连写第一批（关键步骤）

**先跑门控**：

```bash
python3 "$SKILL/scripts/batch_preflight.py" ./我的剧 --from 1 --to 5
```

退出码非 0 就别开写，先按报错修台账。PASS 后它会打印**上下文重建摘要**，接着：

```
/连写 1-5
```

#### 第 6 步：每批收工检查

```text
□ episodes/ 下有 ep001.md ~ ep005.md
□ 每集都过了 validate_episode.py（集内 PASS）
□ 本批跑过 check_chaining.py（跨集），相邻集无 C1 断裂
□ 台账五类账已更新（承接账 + 新伏笔/关系变动/道具易手/规矩引用）
□ 承接账：下一集的「本集承接」已写成上集的「本集断在」原话；上一集的「悬」已改「收」
□ 台账头部两个游标（上一集断在 / 本集须承接）已同步
□ 台账「当前集」已改成 5   ← 忘了这步，下一批直接报 P3
```

#### 第 7 步：循环第 5~6 步，直到全剧完稿

```
第 2 批：preflight --from 6 --to 10   → /连写 6-10
第 3 批：preflight --from 11 --to 15  → /连写 11-15
...
```

**每 5 集**：回读台账，查伏笔超期与称谓漂移。
**每 10 集**：回读回合表，确认没跑出本回合的档位区间。

### 可能出现的问题（S1）

| 问题 | 症状 | 怎么办 |
|---|---|---|
| **第 3 集就跑偏** | 主角开始主动出击，但回合表里她还处在档 1 被动期 | 回读回合表，把该集改回档位内；或提前做攻守转换（但转换点应≈第 4 回合） |
| **台词全是一个味儿** | 遮住名字认不出谁在说 | 跑 `/剧本医生`，重点查语言指纹；回 `05-voice-dialogue.md` 的七类人脸谱 |
| **称谓漂移** | 第 3 集叫「美娟」，第 8 集叫「刘美娟」但台账没记录 | 称谓变化必须落账。查台账人物账的称谓链 |
| **伏笔埋了不收** | 第 30 集时 FB-01 还挂在「埋」 | 门控 P6 会拦住；修法是下一集用一句台词自然带出，别硬塞 |
| **单元硬拉** | 一个矛盾写到第 40 集还没闭环 | 这是最伤剧的漂移。硬帽 20~30 集，到点必须闭环换矛盾（换矛盾不换情绪） |
| **机检一直 FAIL** | 见 §10 报错码表 | 按码修，E2 是体量、E5 是台词超 25 字、E7 是断章字段缺 |
| **主角越写越窝囊** | 观众会骂，20 集后弃剧 | 查「每 10 集至少动用一次底牌」，这是硬配额 |

## 3. 场景 S2：先试水 —— 一句话点子直出 1~5 集

> 适合：想先看这个题材/文风行不行，再决定要不要投 80 集精力。

### 全流程

```
/极速短剧 老太太在儿子家当了三年免费保姆，孙子满月宴上被亲家母
介绍成「家里请的阿姨」，她没吵，回屋翻出一个铁盒。
```

skill 会**静默走完所有门控**，直接给你 1~5 集足额剧本（含档位、黄金前 3 秒、往返回合、断章）。

### 注意事项

- **它是「静默」的**：不会先问你赛道、档位、平台，而是自己判断。如果判断错了，直接说「赛道不对，应该是 F3 寻亲认子，重出」。
- **试水稿不落台账**，别拿来当正式项目的第一批 —— 正式开工仍要走 S1 的第 3 步（落盘四份文件）。
- 试水得到的赛道判断可以直接复用到 `/立项`：把它的结论贴进去。

### 可能出现的问题

| 问题 | 怎么办 |
|---|---|
| 赛道判断不符合你预期 | 明确说「主赛道锁 F1，辅赛道 F4」，别让它猜 |
| 直出的集数不是你要的 | 说「只要 1 集，做完整」或「出 3 集」 |
| 想要它顺便把关键帧/分镜也出了 | **本 skill 只做剧本层**，到断章卡点为止。分镜/成片要接制作类 skill |
| 试水稿想转正式项目 | 手动补四份文件，把试水稿的第 1 集改名放进 `episodes/`，台账「当前集」填 1 |

## 4. 场景 S3：跨会话续写（最容易翻车的场景）

> 适合：写到第 30 集，关了窗口，三天后要接着写。

### 核心原则

**绝对不要说「继续」。** 对话记忆可能已经被压缩，说「继续」= 让它凭残留印象续写 = 称谓、关系、伏笔、档位一起漂。

### 正确做法（全流程）

**第一步，跑门控：**

```bash
python3 "$SKILL/scripts/batch_preflight.py" ./我的剧 --from 31 --to 35
```

**第二步，只读摘要。** 它会打印：

```text
==============================================================
上下文重建摘要（本批只读这一段，不必重读四份全文）
==============================================================
剧名/赛道：F1 婆媳清算
档位/总集数：标准档 / 80 集
情绪契约：让把我当外人的一家人，当众认下我这十年的账   ← 全剧不改
主角：周桂兰（61，忍让型）
底牌：手艺（裁缝，第28集起接活） / 证据（三年记账本） / 钱（老房尾款8万，第38集补）
反派四层：第1层 刘美娟（儿媳）｜第2层 周建军（儿子·可理解动机层）｜...
付费墙：一级 第12集 / 二级 第30集 / 三级 第56集
--------------------------------------------------------------
当前集：30  →  本批：第 31～35 集
本批起点所属：二幕·升级纠缠（16～45）
本批所属单元：单元 B（第 26～52 集）  ⚠ 单元硬帽 20~30 集，到点必须闭环
--------------------------------------------------------------
人物关系现值（写前对齐，称谓不许漂）：
  · 周桂兰 ｜ 主角 ｜ 变动集 —
  · 刘美娟 ｜ 儿媳·敌对（称谓「美娟」） ｜ 变动集 1
--------------------------------------------------------------
待收伏笔（1 条）：
  · FB-01 腌菜坛底的铁盒与记账本（埋于 1，拟收 25）
--------------------------------------------------------------
本批所在回合：回合 2（第 5-8 集）
  证据档：档2：银锁被扔进杂物间
  反驳档：档2：质疑证据效力
```

**第三步，把摘要贴给 skill 再下指令**（这是最稳的沟通方式）：

```
这是台账摘要（当前集 30，单元 B，回合 2，待收伏笔 FB-01）：
<<< 粘贴摘要 >>>
/连写 31-35
```

**第四步**，回到 S1 的第 6 步做收工检查。

### 可能出现的问题

| 报错/症状 | 含义 | 怎么办 |
|---|---|---|
| **P3 集号不连续** | 台账「当前集」没更新（上一批忘了） | 核对 `episodes/` 里实际最后一集，手动把「当前集」改成它 |
| **P6 伏笔超期** | 某条伏笔过了拟定回收集 3 集还没收 | 要么下一批安排收，要么明确标「废」并写原因 |
| **P2 台账头部缺字段** | 台账被手搓，格式不对 | 从 `templates/ledger.md` 重新复制头部 |
| **P1 缺少底稿** | 四份文件不全（常见于换电脑/换目录） | 补齐；找不到就用 `/全剧大纲` 重建 |
| **摘要里「本批所在回合」提示未找到** | 台账回合表只填了一部分 | 先补全本单元 6 回合再开写 |
| **写出来跟上一批语气不一样** | 你没把摘要贴给它 | 贴摘要重写；顺便跑 `/剧本医生` 统一语言指纹 |

## 5. 场景 S4：单集返修 / 补拍

> 适合：第 23 集写得不好要重写；或客户要求补一集。

### 全流程

```
/写剧本 第23集（重写）
问题：这一集主角反击太早，跟回合表对不上——回合表里她这时还在档 3，
应该只是找居委会调解，不该已经亮底牌。请重写，保留原集的断章公式。
```

### 注意事项

- 返修**会让集号跳变**，门控会拦。补拍/返修时加 `--force`：

```bash
python3 "$SKILL/scripts/batch_preflight.py" ./我的剧 --from 23 --to 23 --force
```

- 返修后**必须回改台账**：如果重写改变了关系现值、道具状态或伏笔，逐条更新，否则后面全乱。
- 若返修影响后续剧情（比如这一集提前亮了底牌），**必须连带检查后续 5~10 集的档位**，否则回合结构塌。

### 可能出现的问题

| 问题 | 怎么办 |
|---|---|
| 改完这一集，后面 5 集全对不上 | 先改回合表（全剧大纲），再按新回合表批量返修——不要只改正文 |
| 机检 PASS 但读起来不对 | 机检只管硬指标（体量/字段/字数/复读），读感问题靠 `/剧本医生` 或人工 |
| 改一集花了很久 | 正常。返修比新写贵，做好心理预期 |

## 6. 场景 S5：已有剧本草稿，要诊断精修

> 适合：你手里已经有一份别人写的/自己写的短剧剧本。

### 全流程

**第一步，诊断（会告诉你哪里有病）：**

```
/剧本医生
<<< 粘贴剧本全文 >>>
重点查：① 台词有没有 AI 腔 ② 称谓是否一致 ③ 断章够不够狠
```

**第二步，机检（会告诉你哪条硬指标不合格）：**

```bash
python3 "$SKILL/scripts/validate_episode.py" 我的草稿.md
# 若剧本没写档位，脚本会报 E1，用 --format 指定：
python3 "$SKILL/scripts/validate_episode.py" 我的草稿.md --format standard
```

**第三步，合规过一遍：**

```
/合规审核
<<< 粘贴剧本 >>>
```

**第四步，按诊断结果改。** 常见改法：

| 诊断结果 | 改法 |
|---|---|
| 「开篇在铺垫」 | 前 3 秒直接切冲突顶点（五母型之一），把铺垫挪到后面 |
| 「台词太长」 | 单句压到 12~18 字，爆发金句 8~12 字，硬上限 25 字 |
| 「断章平淡」 | 换四大断章公式之一，停在「手已经抬起来但还没落下」 |
| 「反应像播音腔」 | 反派要市井刻薄、主角要隐忍克制，各自有语言指纹 |
| 「主角太窝囊」 | 加底牌，或把某次忍让改成「记账」式的隐性反击 |

### 可能出现的问题

| 问题 | 怎么办 |
|---|---|
| E1 档位未标注 | 头部加 `【档位】：标准档（90～120 秒）`，或用 `--format` |
| E2 体量不在区间 | 标准档要 350~500 字（去标点口径）。**别注水**，补真内容（加一个升级动作/一句新信息） |
| E4 对白行不足 | 标准档 ≥4 行。静场太多会把黄金前 3 秒拖没 |
| E7 断章字段缺失 | 断章必须五字段齐全：公式/停格画面/停格台词/观众问句/黑屏 |
| E10 台词复读 | 同一句台词出现两次。同一反驳话术跨回合重复＝废回合 |
| 剧本是别的赛道（战神/霸总） | **不是本 skill 的赛道**，用通用短剧 skill |

## 7. 场景 S6：长档（3 分钟/集）项目

> 适合：单集时长要 3 分钟，集数 30/40/50。

### 与标准档的差异

| 维度 | 标准档 | 长档 |
|---|---|---|
| 时长 | 90~120 秒 | 165~195 秒 |
| 正文体量 | 350~500 字 | 650~850 字 |
| 场景 | ≤2 | ≤3 |
| 单集拍数 | 1 拍 | **2 拍 + 中段小钩** |
| 对白行 | ≥4 | ≥8 |
| 全剧集数 | 60/80/100 | 30/40/50 |
| 单元硬帽 | 20~30 集 | 10~15 集 |

### 全流程差异

立项时就要说清：

```
/立项 长档项目，40 集。婆媳清算赛道，主角设定同上。
```

大纲用 `/长档大纲 40集`，之后每集用 `/写长档 第N集`，或 `/连写 长档 6-10`。

**长档的关键约束（三条，缺一即废稿）：**

1. 一集两拍：回合 A ➔ 中段小钩（≈90 秒）➔ 回合 B；
2. 回合 B 的施压与反驳**各升一档**，禁复读回合 A；
3. **中段小钩只抬价不爆点** —— 全集最高潮必须留在集尾断章。

### 可能出现的问题

| 问题 | 怎么办 |
|---|---|
| 90 秒后开始复述回合 A | 回合 B 强制双升级（新证据 + 新代价） |
| 中段小钩写得比集尾还炸 | 把爆点后移，小钩只做「抬价 + 新悬念」 |
| 为了凑 850 字加无意义对白 | 每 30 秒必须有一个新增量（新信息/新行动/新代价） |
| 场景塞到 5~6 个全是过场 | 锁 ≤3，且第 2/3 场必须是升级场（换空间/换对手/换压力） |
| 机检报 E8 | 长档缺【本集中段小钩】，这是必设字段 |
| 长档稿被误判成标准档 | 头部必须写 `【档位】：长档（165～195 秒）`，否则报 E1 |

### 全流程

立项时点明漫剧：

/立项 漫剧项目，80 集漫剧档。养老困境赛道，主角 78 岁老太太，三个儿子推来推去。

## 9. 场景 S8：写到一半，发现方向错了（危机处理）

> 适合：写到第 40 集发现赛道选错、结局不满意、或者用户要改集数。

### 先判断改动级别

| 改动 | 影响范围 | 代价 |
|---|---|---|
| 改台词、改单集节奏 | 1~3 集 | 低，直接返修 |
| 改某单元的对手/闭环 | 1 个单元（20~30 集） | 中，要重排该单元回合表 |
| **改情绪契约** | **全剧** | **极高，等于重做** |
| **改赛道** | **全剧** | **极高** |
| 改集数档（80→100） | 全剧节奏与付费墙 | 高，但可增量补写 |

### 处理流程

**情况 A：只改单元（推荐的最优解）**

多数「方向错了」其实只是单元问题。做法：

```
现在写到第 40 集，单元 B 的对手太弱。我想把单元 C 的终极对手
从「堂亲」改成「偏心分家的老规矩本身」，并让儿子在 B 单元结尾倒戈。
请重排单元 C 的回合表，并标出第 41~45 集需要改的地方。
```

拿到新回合表后，更新 `全剧大纲.md`，再按新回合表返修受影响的集。

**情况 B：改集数（80 → 100）**

```
现在 80 集写到第 40 集，要扩到 100 集。请重排四幕区间、
把单元 C 拆成 C/D 两个单元，并重算三级付费墙落位。
```

**注意**：扩集数最容易犯的错是「注水」。正确做法是**加单元**（新矛盾新对手），不是拉长现有单元 —— 单一矛盾硬帽 20~30 集不能破。

**情况 C：改情绪契约或赛道（剧已经写了一半）**

**诚实建议：不要改。** 情绪契约是全剧锚点，改了等于重做。两个现实选择：

1. **写完这一部**，把想改的做成下一部（推荐）；
2. **保留前 40 集当素材**，重新 `/立项`，重走 S1 全流程 —— 但前 40 集基本要重写。

### 可能出现的问题

| 问题 | 怎么办 |
|---|---|
| 改完单元，前面 30 集也对不上 | 说明改动实际触及了 A/B 接缝。回看「三缝合一」规则，确认旧单元的残渣是否还能生出新矛盾 |
| 扩集数后节奏变拖 | 检查是否把现有单元拉长了。应该是「加单元」而不是「拉单元」 |
| 改完台账没同步 | **台账是唯一事实源**。正文与台账冲突时先停下确认哪边改，不要让它自己圆 |
| agent 擅自改了情绪契约 | 明确说「情绪契约不许改」，并要求它回读 `02-emotional-contract.md` §二 |

## 9.5 场景 S9：双模型分工（Gemini 写正文，DeepSeek 记账）

> 想让**文笔更好的模型写正文**、但**总控和台账留在便宜的模型上**时用这个场景。
> 机制不是「切换模型」，是**委派**：主 agent 不换，正文由子代理产出。所以总控永远是同一个模型。

### 一句话原理

```text
主 agent（账房）＝ DeepSeek：立项 / 大纲 / 分集 / 五类账 / 台账更新 / 跑机检 / 判门控
写手子代理     ＝ Gemini ：只写 episodes/epNNN.md 的单集正文
判定           ＝ 本地 Python：E1~E11 / C1~C4 / P1~P9
```

### 前置：环境里得有一个「写手路由」

DSH 里子代理能用的模型受一份**白名单**限制（settings 的 `subagent-model-selection.allowedModels`）。两个坑：

1. **白名单是按会话固化的**，会话建好之后再改配置**不生效** —— 改完必须**开新会话**。
2. 白名单里只放行了主模型时，子代理只能用主模型，看起来像「Gemini 接不进来」，其实是没放行。

自检（在会话里直接问）：

```text
list_subagent_models                                # 列出可用 provider
list_subagent_models provider=<id>                  # 列出该 provider 的模型与 reasoning 档位
```

报 `not allowed for this Session` ＝ 白名单没放行（或本会话是旧策略，需开新会话）；
报 `is not registered` ＝ provider 本身没配好。

### 全流程

| 步骤 | 你/agent 做什么 |
|---|---|
| 1 | 正常走 S1 的第 1～4 步（立项 → 大纲 → 落盘 → 分集规划）。**这些全在主 agent 上做。** |
| 2 | 说 `/连写 6-10`。门控先跑（`batch_preflight.py`），PASS 才开工。 |
| 3 | 主 agent 挑写手路由 → 按 `templates/writer-handoff.md` 填交接单 → 用 `subagent` 派活 |
| 4 | 写手写完回报：集号 / 每集机检结果 / 断章公式与停格物件 |
| 5 | **主 agent 自己重跑机检**（`validate_episode.py` 逐集 + `check_chaining.py` 跨集），**不看写手汇报** |
| 6 | 主 agent 更新台账：承接账逐集补行、本集断在 / 下集承接、上一集「悬」改「收」、头部两游标 |
| 7 | 跑下一批门控，重复 2～6 |

**一批建议 3～5 集。** 太少不划算，太多写手会在批次后段开始漂称谓和体量。

### 为什么换写手不会写崩（重点）

写手和账房之间的接口是**承接账**，而这个契约是**按物件签的，不是按文字签的**：

- `check_chaining.py` 的 **C2** 只问「承接账声明的物件有没有出现在下一集开场窗口里」，**不问措辞**；
- 所以写手可以自由改文笔、换句式、重写镜头，只要那一帧里的**东西**还在，就通过；
- 把物件换掉或改丢 → 报 C2。

> **文笔归写手，账归账房，物件的存续由机检裁决。**

### 三条禁令（说给 agent 听也行，写进交接单更好）

1. **写手不许改 `台账.md`。** 只读。一改账，跨模型契约立刻失效。
2. **必须用 `subagent`，不能用 `subagent_fork`。** fork 不支持模型选择，provider/model 与父相同 —— 用它等于没换模型。
3. **判定结果不能由写手自评。** 写手说「全部 PASS」不算数，账房必须自己重跑。

### 可能出现的问题（S9）

| 问题 | 怎么办 |
|---|---|
| 子代理报 `not allowed for this Session` | 白名单没放行，或本会话是旧策略。**开新会话**再试 |
| 子代理报 `not registered` | provider 没配好（缺 `baseURL` / `api` / credential 引用名）。去 Settings → Models 页配 |
| 委派出去但写手回的是「我不会」或空话 | 交接单没填全。写手是**全新会话**，不继承任何上下文，漏一项它只能编 |
| 写手把 `台账.md` 一起改了 | 立刻 `git status` 查出来，把台账还原到账房版本，重申「账只读」，重派该集 |
| 写手写的集子体量忽长忽短 | 交接单里要写明**去标点口径**的体量区间；机检 E2 兜底 |
| 想省事让写手顺便更新台账 | **不行。** 台账是跨模型契约，必须单一所有者（账房）。这也是它唯一的 bug 来源 |
| 中途换了写手模型（比如 Gemini→别的） | 不用改账、不用改分集规划。契约是物件级的，**换写手只影响文笔** |
| 没有 Gemini 或任何第二个模型 | 不用这个场景。主 agent 自己写，机检照样拦，只是文笔由主模型决定 |

## 10. 通用故障排查

### 10.1 单集机检报错码（`validate_episode.py`）

| 码 | 含义 | 怎么修 |
|---|---|---|
| **E1** | 档位未标注（头部没写【档位】） | 头部加 `【档位】：标准档（90～120 秒）`，或 `--format standard` |
| **E2** | 正文体量不在区间 | 标准 350~500 / 长档 650~850 / 漫剧 260~400 / 漫剧长档 520~680（去标点口径）。**补真内容，别注水** |
| **E3** | 场景数超上限 | 标准 ≤2、长档 ≤3。砍过场场，只留升级场 |
| **E4** | 对白行不足 | 标准 ≥4、长档 ≥8。静场太多会拖垮黄金前 3 秒 |
| **E5** | 单句台词 >25 字 | 拆句。常规 12~18 字，爆发金句 8~12 字 |
| **E6** | 缺【黄金前3秒钩子】 | 补字段，且必须是五母型之一 |
| **E7** | 断章缺失或五字段不全 | 断章要：公式 / 停格画面 / 停格台词 / 观众问句 / 黑屏 |
| **E8** | 长档缺【本集中段小钩】 | 长档必设，≈90 秒处，只抬价不爆点 |
| **E9** | 命中合规高危词 | 按 `07-compliance-taboo.md` §三 转译表替换，**情绪强度不降，只降表达烈度** |
| **E10** | 台词复读 | 同一句台词出现两次。同一反驳话术跨回合重复＝废回合 |
| **E11** | 第一句台词以称呼语起手 | 开篇禁令。改成直接进冲突 |
| W1 | 出现抽象心理词 | 改成可观测动作（「她很伤心」→「她用围裙角擦了三下眼睛」） |
| W2 | 缺【本集小账】 | 提示，非强制 |

```bash
# 自检脚本本身
python3 "$SKILL/scripts/validate_episode.py" --self-test
```

### 10.2 跨集承接报错码（`check_chaining.py`）

| 码 | 含义 | 怎么修 |
|---|---|---|
| **C1** | 第 N→N+1 集断裂：上一集断章的物件/事件没出现在下一集开场 | 回读承接账，把上一集断章在本集开场 15 秒内兑现；确实不接就标「废」并写理由 |
| **C2** | 声明了要接某物件，但开场窗口里没有 | 正文按声明重写——**不是改账** |
| **C3** | 断章超期：承接账标「悬」已 ≥3 集未兑现 | 尽快兑现，或改「废」并写理由（上限连续 2 集） |
| **C4** | 承接账缺行 / 「上集断在」与「下集承接」不是同一件事 | 补齐缺行；两栏必须原话一致 |
| D1 | 诊断（不计 FAIL）：断章物件复活延迟 ≥3 集 | 说明钩子凉了，考虑提前收或删 |

```bash
python3 "$SKILL/scripts/check_chaining.py" .                 # 体检
python3 "$SKILL/scripts/check_chaining.py" . --csv out.csv   # 逐对明细，便于人工比对
python3 "$SKILL/scripts/check_chaining.py" --self-test
```

### 10.3 批次开工门控报错码（`batch_preflight.py`）

| 码 | 含义 | 怎么修 |
|---|---|---|
| **P1** | 四份底稿缺失 | 补齐；找不到就用 `/全剧大纲` 重建 |
| **P2** | 台账头部缺字段 | 从 `templates/ledger.md` 重抄头部（11 个字段，含 `上一集断在` / `本集须承接`） |
| **P3** | 集号不连续 | 台账「当前集」没更新。核对实际最后一集后改；跳写加 `--force` |
| **P4** | 人物账为空 | 至少登记主角与第 1 层反派（未建档不得给台词） |
| **P6** | 伏笔超期 | 超拟定回收集 3 集还没收。安排收，或标「废」并写原因 |
| **P7** | 区间非法 / 超出总集数 | 检查 `--from/--to` 与台账「总集数」 |
| **P9** | 断章超期 | 承接账里「悬」已 ≥3 集未兑现。兑现或标「废」 |
| P5 / P8 | 情绪契约过长 / 单元划分不匹配 | 提示级。契约压到 ≤60 字；单元划分改成 `A(1-25) / B(26-52) / C(53-80)` |

```bash
# 自检脚本本身
python3 "$SKILL/scripts/batch_preflight.py" --self-test
```

### 10.4 症状速查（机检不报但你觉得不对）

| 症状 | 根因 | 怎么修 |
|---|---|---|
| **上一集的钩子这集完全不提** | 缺承接账，写手每集只有状态快照 | 读本集【上集承接】＝上一集承接账的「本集断在」；开场 15 秒先兑现再起新钩子。跑 `check_chaining.py` 定位 |
| **几乎每集都用全新钩子开场** | 分集规划是平行属性表而非链条 | 分集规划改链条式：写完 N 的「集尾断在」再写 N+1 的「承接」，两者必须同一句 |
| 遮住名字认不出谁在说 | 语言指纹没生效 | `/剧本医生` 重点查七类人脸谱 |
| 上集敌对这集和好 | 关系现值没有触发事件 | 查台账人物账，关系变动必须有集号与触发事件 |
| 死人开口 | 状态没落账 | 只能是回忆闪回，且需标注 |
| 道具穿越 | 道具账没记易手/损毁 | 断章用到道具特写前，先核对持有者 |
| 规矩失忆 | 前文立的家规后文当不存在 | 规矩被违反必须当场被指出 |
| 主角越写越窝囊 | 底牌没用 | 硬配额：每 10 集至少动用一次底牌 |
| 反派坏得没道理 | 第 2 层缺可理解动机 | 「我也难」必须是处境，不是台词 |
| 结局想打一顿收尾 | 违反硬规矩 3 | 结局必须落在「当众认账 + 秩序伦理修复」 |
| 集数越写越多 | 注水 | 单一矛盾 ≤30 集闭环，加单元而不是拉单元 |

## 11. 沟通反例：别这么说

| ❌ 别这么说 | 为什么不行 | ✅ 改成 |
|---|---|---|
| 「继续」 | 靠残留记忆续写＝必漂 | 「读台账摘要（附上），`/连写 31-35`」 |
| 「一次给我 30 集」 | 上下文会爆，中途质量断崖 | 「分 6 批，每批 5 集，每批先跑门控」 |
| 「帮我写个短剧」 | 没赛道没档位，它只能猜 | 「80 集标准档，F1 婆媳清算，红果」 |
| 「把它改得好一点」 | 没有判据，改出来还是不对 | 「第 23 集反驳太早，回合表里这时是档 3，改成找居委会调解」 |
| 「主角惨一点」 | 违反硬规矩（不许纯受害者） | 「加一张底牌，让她的忍让是记账式的」 |
| 「结局打她一顿解气」 | 一票否决（暴力泄愤） | 「结局落族亲聚会当众认错 + 赡养协议签字」 |

| 「顺手把分镜也出了」 | 超出 skill 边界 | 剧本到断章为止，分镜另接制作类 skill |

### 12.4 三个脚本

### 12.5 三条硬规矩（违反即返工）

1. **不许把老人写成纯受害者** —— 必须有「藏着的底牌」，每 10 集至少动一次。
2. **不许子女反派一坏到底** —— 四层反派中至少一层要有可理解的动机。
3. **不许暴力泄愤收尾** —— 结局必须落在「当众认账 + 伦理秩序修复」。

### 12.6 已知边界（skill 目前不做的事）

| 你想做 | 现状 | 替代做法 |
|---|---|---|
| 网文长篇 → 分集改编 | 本 skill 无此流水线 | 先自己提炼成一句话点子 + 赛道，再走 `/立项` |
| 分镜 / 角色三视图 / 视频提示词 | 明确不做 | 剧本到断章为止，接制作类 skill |
| 悬疑 / 规则怪谈 / 战神赘婿 / 霸总甜宠 | 不是本赛道 | 用通用短剧 skill |
| 中途更换情绪契约或赛道 | 没有低成本方案 | 写完这部，下一部再做（见 §9 情况 C） |
| 一次产出 20 集以上 | 不支持一口气连写 | 分批 + 台账串起来（见 §1 原则二） |
