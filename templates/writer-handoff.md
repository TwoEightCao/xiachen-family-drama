# 写手交接单（Writer Handoff）

> **用途**：账房（主 agent）把「单集正文」外包给写手子代理（默认 Gemini 等非本地模型）时，填好本单**原样作为子代理的提示词**。
>
> **为什么需要它**：子代理是 `spawn` 出来的**全新会话**，不继承任何对话上下文 —— 本单是它唯一的信息来源，漏一项它就只能编。
>
> **配套规程**：`SKILL.md` §二「模型分工」。分工的接口是**承接账**，按物件签约，不按文字签约。

---

## 一、 账房怎么用

```text
1. 挑写手路由（每次都要现查，不要凭记忆）：
   list_subagent_models                       # 列出可用 provider
   list_subagent_models provider=<id>          # 列出该 provider 的模型
   优先级：① provider/model 名里含 gemini / google 的 → ② 任何非本地主模型的路由 → ③ 都没有 → 退化为主 agent 自己写
2. 填本单（下面「三、交接单正文」那段整个复制，填掉 <...>）
3. 派活：subagent(provider="<写手 provider>", model="<写手 model>",
                 reasoning_effort="high", prompt="<填好的交接单>")
   ⚠️ 必须用 subagent（spawn）。不要用 subagent_fork —— fork 不支持模型选择，
      provider/model 与父相同，用它等于没换模型。
4. 写手回报后，账房立刻验收（见「五、账房验收」）。写手说自己过了不算数。
```

**一批几集**：建议 **3～5 集**一批。太少则上下文反复重建不划算；太多则写手会在批次后段开始漂称谓与体量。

---

## 二、 三条不可协商的边界

| 边界 | 含义 |
|---|---|
| **账只读** | 写手**不许以任何理由修改** `台账.md`、`分集规划.md`、人物圣经、立项单。它只能读。 |
| **只写正文** | 写手只能创建/覆盖 `episodes/epNNN.md`。 |
| **承接照抄** | 上一集承接账的「本集断在」那一句，要**原话照抄**进本集的 `【上集承接】`，不许改写。 |

> 写手一改账，「承接账」这个跨模型契约立刻失效 —— 这不是风格问题，是数据完整性问题。

**这三条是「规格级」约束，不是沙箱。** 必须清楚：子代理继承与主 agent 相同的文件系统权限，**DSH 目前没有 per-subagent 的文件范围限制**（`subagent` 工具的参数只有 `provider` / `model` / `reasoning_effort` / `prompt` 等，没有路径白名单）。所以这三条的执行靠两件事，缺一不可：

1. **交接单里写清楚**（第 5 步的提示词里已包含）—— 这是让写手**不去做**；
2. **账房事后机械核验**（见「五、账房验收」第 1 步）—— 这是让写手**做了会被发现**。

**只靠第 1 条等于没约束。** 不要因为交接单里写了「只读」就跳过验收第 1 步。

## 三、 交接单正文（整段复制给写手）

```text
你是「写手」，只负责一件事：把指定集数的剧本正文写进 episodes/。你不是账房。

【你的角色边界 · 违反即废稿】
1. 不许修改 台账.md / 分集规划.md / 人物圣经 / 立项单 —— 一个字都不许动。台账对你只读。
2. 你只能创建或覆盖 episodes/epNNN.md，不许碰项目里任何其他文件。
3. 不许改写承接账里的任何一句话。上一集「本集断在」的原话，要照抄进本集【上集承接】。

【项目信息】
项目目录：<绝对路径>
skill 目录：<绝对路径，例：~/.agents/skills/xiachen-family-drama>
本批集数：第 <X> 集 ～ 第 <Y> 集
档位：<标准档 | 长档 | 漫剧档 | 漫剧长档>

【必读，按序读完再动笔】
1. <skill>/references/03-audience-paywall.md §四 —— 档位规格（唯一权威）
2. <skill>/references/06-hook-cliffhanger.md —— 黄金前 3 秒五母型 + 四大断章公式
3. <skill>/references/05-voice-dialogue.md —— 台词七维去 AI 味 + 亲属称谓
4. <skill>/templates/episode-format.md —— 排版模板，逐字段照填，不许自创字段
5. <项目>/台账.md —— 五类账全读，其中「承接账」逐字读
6. <项目>/分集规划.md 里本批这几集的条目
7. 上一集正文 episodes/<上一集编号>.md —— 只读，用来对齐语气与人物状态

【逐集规程 · 三集都要按这个顺序走】
① 承接核对：把本集【上集承接】写成上一集承接账「本集断在」的原话。
   若本集是这批的第一集，它的承接来自台账；若是批内后续集，承接来自你刚写的上一集断章。
② 写正文：按 <skill>/templates/episode-format.md 对应档位的模板逐字段填。
   开头顺序是死的：【上集承接】前 15 秒兑现 → 之后才是黄金前 3 秒（五母型之一）。
   开场不是自由发挥位，是上一集断章的兑现位。
③ 写集尾：【本集断章卡点】按 references/06 的四大公式选一个，五个字段填满。
   停格画面必须写成「可拍摄的一帧」（谁的手 / 哪件东西停在什么位置），
   且这一帧里必须出现承接账本行登记的物件 —— 因为下一集要照着它开场。

【硬性体量（去标点口径，机检会数）】
- 标准档：正文 350~500 字（漫剧 260~400），场景 ≤2，对白行 ≥4，单句 ≤25 字
- 长档：正文 650~850 字（漫剧 520~680），场景 ≤3，对白行 ≥8，双回合 + ≈90 秒中段小钩

【写完必须自检，FAIL 就地修到 PASS】
python3 <skill>/scripts/validate_episode.py <项目>/episodes/epNNN.md
（脚本报的 E1~E11 逐条修。档位字段缺失报 E1，体量报 E2，台词超 25 字报 E5，断章字段缺报 E7。不许把 FAIL 的稿子交回来。）

【回报格式 · 只报这几项，不要复述正文】
1. 写完的集号清单
2. 每集的 validate_episode.py 结果（PASS / FAIL + 若 FAIL 说明为何你认为可以交）
3. 每集的断章公式名 + 停格画面里的物件名
4. 你兑现不了的「悬」钩子（如果有），以及你把它挂到了第几集
```

## 四、 常见翻车与预防

| 症状 | 根因 | 预防 |
|---|---|---|
| 用全新钩子开场，完全不接上集 | 写手把开场当自由创作位 | 交接单第 ① 步前置；写后由 `check_chaining.py` C1/C2 拦 |
| 写手改了 `台账.md` | 边界没写清或写手「好心」同步 | 交接单第一段三条禁令；验收时 `git status` 查台账是否被动过 |
| 批到第 4、5 集称谓开始漂 | 批次太长 | 一批 ≤5 集；每批重新发一次交接单 |
| 体量忽长忽短 | 没给「去标点口径」 | 交接单硬性体量段已写明；机检 E2 兜底 |
| 写手把承接的物件换掉了 | 它想「润色」 | C2 报「声明要接 X，开场窗口内没有 X」→ **改正文，不是改账** |
| 写手说「已全部 PASS」但机检不过 | 自评不可信 | 账房必须自己重跑一遍，不看写手汇报 |

## 五、 账房验收（写手回报后立刻做，不可跳过）

**1. 写入是否越界** —— 这是**唯一能证明写手没动账的机械手段**，必须做。项目目录**不一定是 git 仓库**，所以给两条路。

*路线 A（推荐，尤其 80 集长篇）：先给项目目录 `git init`。*

```bash
cd <项目目录> && git init && git add -A && git commit -m "baseline: 派活前"
# 写手回报后
git status --short        # 只应出现 episodes/ 下的改动
git diff --stat           # 若 台账.md / 分集规划.md 出现在这里 → 写手越界，立即回退
```

代价是一次 `git init`，换来的是每集可 diff、可回滚 —— 长篇连载值这个钱。

*路线 B（不想 git init 时的最小做法）：派活前后各拍一次哈希快照。*

```bash
# 派活前
md5 -q <项目目录>/台账.md > /tmp/ledger.before      # macOS；Linux 用 md5sum
# 写手回报后
md5 -q <项目目录>/台账.md > /tmp/ledger.after
diff /tmp/ledger.before /tmp/ledger.after && echo "台账未被改动 ✓"
```

对 `分集规划.md` / 人物圣经 / 立项单 同样拍一遍。

> ⚠️ 不要用 `ls -l` 看时间戳代替 —— 同一秒内的修改会漏掉，而写手改账通常是瞬间完成的。
> ⚠️ 若项目目录不是 git 仓库，`git status` 会直接报 `not a git repository`；别把这句报错当成「检查通过了」。

**2. 集内机检**（逐集）

```bash
python3 "<skill>/scripts/validate_episode.py" <项目>/episodes/epNNN.md
```

**3. 跨集机检**

```bash
python3 "<skill>/scripts/check_chaining.py" <项目目录> --from <X> --to <Y>
```

**4. 台账登记**（这一步必须账房自己做，不许外包）
承接账逐集补行 → 本集断在 / 下集承接 / 上一集「悬」改「收」并填兑现集 → 头部两个游标同步。

**5. 批次门控**

```bash
python3 "<skill>/scripts/batch_preflight.py" <项目目录> --from <下一批首集> --to <下一批末集>
```

**6. 任一步 FAIL**：先判是「写手写错」还是「账房分集规划本身有洞」——
前者退回写手重写该集；后者由账房先改分集规划与承接账，再重派。

> **判定永远归账房，不归写手。** 写手的自评、自信度、以及「我觉得接住了」都不构成验收证据。
